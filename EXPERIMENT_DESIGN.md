# Pre-Registered Experimental Design: Cooperative Distributed Detection with Time-Decayed Graph Evidence

**Status:** Phase 0 frozen design for review. No test campaign may execute until this document and `params_frozen.yaml` are approved.

**Scope:** This document pre-registers the simulation-only evaluation for the design paper's Sections 6, 8, and 9. It resolves the known specification ambiguities listed in the build prompt and defines the immutable experimental plan, tuning boundaries, metrics, statistics, and reproduction expectations.

## 1. Phase-0 Freeze Rules

1. Thresholds, weights, decay rates, grids, random seed ranges, calibration settings, and matched-budget procedures are frozen in `params_frozen.yaml` before any test campaign runs.
2. Tuning is allowed only on validation splits. Every tuning run writes a raw result and tuning-log record.
3. Test splits are never inspected during tuning. Any deviation from this design is recorded in `DEVIATIONS.md` before results are interpreted.
4. Censoring is reported explicitly. Undetected campaigns, abstentions, undefined metrics, failed runs, and partition-induced missing observations are never silently excluded.
5. All detector comparisons use paired campaigns, topologies, telemetry streams, perturbations, and seeds.
6. No numeric claim may appear in `REPORT.md` unless it is traceable to a raw `results/*.json` file generated by a run.
7. The evaluation is simulation-only unless the optional LANL loader is explicitly approved and its label-scope audit is completed before any LANL metric is computed.

## 3. Systems Under Test

### 3.1 Baselines B0--B5

| ID | Name | Description |
| --- | --- | --- |
| B0 | Local-only | Each host detects from its own local evidence only; no graph reconstruction or cooperation. |
| B1 | Central streaming | Centralized detector sees the identical telemetry stream with a configurable ingest/batch delay. |
| B2 | Static graph | Uses aggregated non-temporal graph evidence without elapsed-time decay. |
| B3 | Temporal-graph-only | Uses elapsed-time graph evidence and ranking but no cooperative influence exchange. |
| B4 | Cooperation-only | Uses local and cooperative evidence without temporal graph-origin ranking. |
| B5 | Full | Local evidence, gated budgeted cooperation, decayed temporal graph view, stability clocks, and ranking with rootness contradiction. |

### 3.2 Safety Ablations

| Ablation | Difference from B5 | Purpose |
| --- | --- | --- |
| No source budget | Removes per-source sub-budget while retaining aggregate budget. | Tests colluding or dominant sender containment. |
| No aggregate budget | Removes recipient rolling aggregate budget while retaining source sub-budget. | Tests flood containment from many senders. |
| No diversity | Removes diversity requirement in cooperative uptake. | Tests monoculture or single-corridor amplification. |
| No local gate | Allows cooperative uptake without local evidence gate. | Tests zero-local-evidence safety. |
| No dedup | Removes event-ID contribution deduplication and double-count tracking. | Tests double-counting sensitivity. |
| No freshness | Disables elapsed-time freshness decay in influence and graph evidence. | Tests stale evidence amplification. |

## 4. Pre-Registered Mechanism Resolutions

### 4.1 Eq. 2 Rolling Budget Consumption

Recipient `j` maintains a rolling budget `B_j(W)` over elapsed-time window `W`. Accepted influence from sender `i` is accumulated as consumed budget. The acceptance cap for a new message is `min(requested_influence, remaining_budget_j, remaining_source_subbudget_ij)`, where remaining budget is the frozen window budget minus influence already accepted inside the window. The `min()` is never recomputed from a fresh full budget per message. A per-source sub-budget is applied as defense-in-depth.

### 4.2 Eq. 5 Clock Semantics

Earliness `E` uses the first-alert time. Stable-evidence time from Section 6.5 is used only to qualify candidates and to report a second timeline. All latency tables report both first-alert latency and stable-evidence latency.

### 4.3 Eq. 5 Contradictions `V`

Contradiction penalty `V` includes a rootness contradiction. A candidate origin with a high-evidence, temporally consistent incoming edge from another candidate receives a strong penalty. This is intended to reduce loud-first-hop inversion where the first compromised internal hop outranks the true origin.

### 4.4 Double-Counting Rule

Every event carries a unique immutable event ID. If one event contributes to both local node evidence `L_n` and path/edge evidence `P_uv`, both contributions retain that ID. The default ranking combines both channels. A required sensitivity variant halves one channel for shared event IDs and reports the delta for headline RQ1 and RQ2 outcomes.

### 4.5 Elapsed-Time Decay

All decay functions use elapsed wall-clock/event timestamps, not tick count. Decayed operational graph evidence follows Eq. 4 and must remain bounded in `[0, 1]` under event storms. Tick-based decay is prohibited.

## 5. Low-Rate Campaign Grid

### 5.1 Factors

| Factor | Levels |
| --- | --- |
| Inter-hop dwell | Fast, slow, ultra-slow beyond decay horizon |
| Security-relevant events per hop | 0--1, 2--3, many |
| Anomaly amplitude | Faint, moderate |
| Path length | 3, 6, 10 |
| Branching | Chain, tree |
| Edge reuse | One-time, corridor re-use |
| Credential type | User, service, admin |
| Origins | 1, 2, unknown/external |

The full factorial grid has `3 * 3 * 2 * 3 * 2 * 2 * 3 * 3 = 1944` cells per topology family, before adversarial variants. The frozen design uses a resolution-preserving fractional-factorial subset for feasibility. The subset is generated by a deterministic balanced sampler that preserves all one-way marginals exactly where possible and covers every pairwise interaction at least once per topology family. The sampler target is 216 low-rate cells per topology family for validation and 216 disjoint low-rate cells per topology family for test.

### 5.2 Campaign Replication

Each selected scenario cell is run with paired random seeds across all systems. Initial campaign count per cell is set by the power analysis in Section 12 and may be increased only before the freeze if validation-only power diagnostics show the pre-registered assumptions are violated.

## 6. Topology Families

1. **Enterprise-120:** At least 120 nodes with departments, user workstations, servers, domain-controller-like nodes, admin nodes, chatty service edges, and sparse cross-department administrative paths.
2. **Enterprise-500:** Approximately 500 nodes with the same typed structure, multiple departments, shared services, multiple DC/server clusters, admin hubs, and heterogeneous edge rates.
3. **Flat/degenerate stressor:** Flat peer-like graph with weak hierarchy and high ambiguity, included to stress root attribution and detect structural artifacts.

All topology instances are generated from frozen seeds. Validation and test use disjoint seed ranges and disjoint scenario-cell assignments.

## 7. Benign Background and Telemetry Observability

Benign background includes admin bursts, service-account activity, chatty service corridors, routine authentication, intermittent failed logins, and benign maintenance paths. Telemetry observability is a first-class parameter controlling event loss, partial visibility, and corridor-level false evidence. The generator must include false evidence that can connect two suspicious nodes so path reconstruction precision cannot be structurally forced to approximately 1.0.

## 8. Adversarial and Fault Suite for RQ3

The RQ3 suite is applied to paired clean campaigns and to selected low-rate cells spanning all topology families.

| Class | Frozen variants | Metric focus |
| --- | --- | --- |
| Replay | Replay stale high-score messages and stale path events. | Benign elevations/host-hour, attribution shift, cascade size. |
| Flooding | High-rate influence messages and high-rate benign-looking events. | Saturation rate, max cascade size, aggregate budget exhaustion. |
| Collusion | `k in {1, 3, 5}` compromised sensors forge maximal-influence messages. | Source concentration, source-budget containment, false alerts. |
| Silence | Sensors on the true path suppress reports. | Censored detection, attribution shift, stable-evidence delay. |
| Clock skew | Sender and event timestamps skewed by small and large positive/negative offsets. | Stable-evidence failures, latency error, freshness degradation. |
| Message loss | 1% and 10% random loss. | Coverage, latency, recovery. |
| Delay/reorder | Delayed and reordered messages with frozen distributions. | First-alert/stable-time disagreement, attribution shifts. |
| Partition/recover | One partition-and-recover scenario per topology family. | Recovery time, missed evidence, post-recovery cascade. |

At least one degradation scenario must be reported plainly, even if B5 remains better than a baseline on other outcomes.

## 9. Metrics and Censoring Rules

### 9.1 Detection and Latency

- Detection coverage: fraction of campaigns with an alert before the campaign ends plus the censoring horizon.
- First-alert latency: first alert time minus attack start time, censored when no alert occurs.
- Stable-evidence latency: first stable-evidence time minus attack start time, censored when no stable evidence occurs.
- Time-to-threshold curves over elapsed time.

### 9.2 False Alerts and Benign Elevation

- False alerts per host-day and false alerts per host-hour.
- Benign elevations per host-hour for adversarial/fault experiments.
- Matched-budget false-alert rate achieved on validation and verified on test.

### 9.3 Attribution and Ranking

- Top-1 origin accuracy, top-3 origin accuracy, mean reciprocal rank, attribution rank of true origin, unknown-origin correctness, abstention rate, and attribution shift under adversary.
- Rootness inversion frequency: rate at which a downstream first hop outranks the true origin when the true origin is observable.

### 9.4 Cooperation Safety

- Max cascade size.
- Saturation rate of aggregate and per-source budgets.
- Source contribution concentration, including top-source share and effective number of sources.
- Fraction of cooperative uptake with zero local evidence, expected to be zero for B5.

### 9.5 Systems Metrics

- Events/sec throughput.
- Memory per 1e6 events.
- Messages per sensor.
- Bytes per sensor.
- Attribution latency.
- Recovery time after partition.

### 9.6 Censoring

Undetected campaigns, abstentions, failed stable-evidence qualification, unknown-origin predictions, and unavailable metrics remain in denominators where applicable and are tagged with explicit censoring reasons in raw results. Latency summaries use survival-aware summaries and paired censored comparisons where needed; uncensored-only summaries are labeled as descriptive and not used for headline claims.

## 10. Matched False-Alert Budget Procedure

1. On validation benign-only streams and validation attack streams, sweep each detector's threshold grid independently.
2. Select the operating threshold that meets the shared false-alert budget of 0.05 false alerts per host-day with the smallest absolute validation error; ties choose the threshold with lower false-alert rate.
3. Freeze selected thresholds in `params_frozen.yaml` before any test execution.
4. Apply frozen thresholds unchanged to test runs.
5. If a detector cannot reach the shared budget on validation, mark it as budget-infeasible and report the closest achievable validation false-alert rate; test comparisons involving that detector are labeled accordingly.

## 11. Calibration Plan for RQ5

Calibration uses held-out topologies and held-out campaign types not used for threshold tuning or final test claims. Features include ranking score components, contradiction penalties, stability indicators, evidence age, source concentration, and abstention margin. Isotonic regression and Platt scaling are trained only on calibration-validation data. Metrics are Brier score, expected calibration error, reliability plots, negative log loss when defined, abstention-coverage curves, and accuracy conditional on coverage. Calibration outputs are frozen before test calibration evaluation.

## 12. Statistics and Power Analysis

### 12.1 Paired Estimation

All headline RQ1--RQ3 comparisons are paired by scenario cell, topology seed, campaign seed, telemetry stream, and adversarial/fault injection seed. Effect sizes include paired mean/median latency differences, relative latency changes, paired coverage differences, paired accuracy differences, and paired false-alert differences.

### 12.2 Confidence Intervals and Tests

- 95% confidence intervals use paired bootstrap with at least 10,000 resamples.
- Paired permutation tests are used for continuous paired deltas when censoring permits.
- Paired binomial or exact sign tests are used for paired binary outcomes.
- Every table states `n`, censoring count, abstention count where applicable, and number of bootstrap resamples.
- Multiple comparisons are grouped by RQ and controlled with Benjamini-Hochberg false discovery rate for secondary outcomes. Primary outcomes remain pre-specified and are reported with unadjusted and adjusted values.

### 12.3 Power Analysis

Target: detect a 15% relative latency change at alpha 0.05 and power 0.8 in paired comparisons. Frozen planning assumptions are: coefficient of variation of paired latency deltas <= 0.8, within-pair correlation >= 0.5, and effective uncensored detection rate >= 0.8. Under these assumptions, the initial campaign replication target is 40 campaigns per selected cell, producing at least 32 expected uncensored paired observations per cell and substantially larger pooled RQ-level paired samples. If validation-only diagnostics show effective uncensored rate below 0.8, the number of campaigns per cell may be increased before test execution and must be logged as a freeze-time design update.

## 13. Splits and Seed Ranges

| Split | Purpose | Seed ranges | Cell access |
| --- | --- | --- | --- |
| Validation | Threshold tuning, fractional-grid diagnostics, power diagnostics, calibration training. | Topology seeds 1000--1999; campaign seeds 100000--199999; adversary seeds 300000--399999. | Validation cells only. |
| Calibration holdout | RQ5 held-out topology and campaign-type calibration. | Topology seeds 2000--2499; campaign seeds 200000--249999; adversary seeds 400000--449999. | Calibration cells only. |
| Test | Final frozen claims. | Topology seeds 5000--5999; campaign seeds 500000--599999; adversary seeds 700000--799999. | Test cells only; never touched during tuning. |

Scenario cells are assigned to splits by deterministic hashing of the full factor tuple plus topology family, with disjoint validation, calibration, and test assignments. Test-cell membership is written before tuning starts and not modified after freeze.

## 14. Reproducibility Requirements

The final testbed must provide one-command reproduction through `make all` or `python run.py --all`. The repository will include committed seeds, experiment YAML files, frozen config, and a dependency lockfile. Generated raw results live in `results/` and generated figures/tables live in `figures/` and `tables/`. `REPORT.md` is generated and every claim cites source result files.

## 15. Dependency Policy

The initial allowed dependency set is `numpy`, `networkx`, `pandas`, `matplotlib`, `scipy`, and `pyyaml`. Additional dependencies require approval before being added.

## 16. Phase Gate

Implementation beyond scaffolding is blocked until this Phase-0 design and `params_frozen.yaml` are approved. After approval, phases proceed in order: core engine, scenario generator, baselines/ablations, adversarial/fault suite, metrics/statistics, calibration, optional LANL loader, and generated report/figures.
